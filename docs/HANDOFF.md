- **Одна задача = одна ветка = один Pull Request.** Никогда не пушить в `main`.
  Ветку бери ту, что указана системой для сессии; если она совпадает с уже
  влитой — пересоздай от свежего main: `git fetch origin main && git checkout -B <ветка> origin/main`.

- Весь текст интерфейса — на трёх языках (ru, uz-латиница, en) через `lib/strings_*.dart`.
  Тест `test/strings_test.dart` это проверяет (новый файл строк — добавить в тест и в `lib/strings.dart`).

  `flutter test`. После PR — дождаться зелёной проверки `build-apk` в Actions
  (подпишись на события PR и поставь напоминание через ~50 минут как страховку).
- Внешние API сначала проверять **реальными запросами curl**, образцы — в `test/fixtures/`.
  Никаких выдуманных данных. Если адрес закрыт сетью — назови мне точный адрес.
  Если документация недоступна — опирайся на исходники официальных клиентов
  (так делали для Zotero: код Zotero и pyzotero) и честно напиши, что не проверено вживую.

  package name `app.scinode.scinode`. Папку `android/` в репозиторий не добавлять
  (Android-настройки — шагами `sed` в `build.yml`).
- Если меняешь Firestore — правь `firestore.rules`, прогоняй тесты эмулятора и давай

## 5. Новое большое направление: «Scinode Аналитика» (продаваемый продукт)
Идея владельца: сделать аналитику науки на открытых данных — альтернативу дорогим
SciVal / Pure / Dimensions **для региона (Узбекистан, Центральная Азия, СНГ)** —
и продавать: **учёным ~$5/мес**, **вузам и лабораториям ~$100 за 3 месяца**.

### 5.1 Честная позиция (говорить так и в интерфейсе)
- У Scopus/WoS преимущество — курируемые данные и признание министерствами. Мы не
  копируем их, а даём **быструю, понятную и дешёвую аналитику на открытых данных**
  с прозрачной методикой и оговоркой: «Индикаторы рассчитаны по открытым данным
  OpenAlex и др.; возможны неточности привязки авторов и организаций».
- Никакого парсинга Scopus/WoS/Google Scholar. Только открытые API с разрешающими условиями.

### 5.2 Источники данных (условия — **перепроверить на сайтах** перед использованием)

| ROR (`api.ror.org`) | реестр ~120 тыс. организаций, ID, страна, статус | CC0 |

### 5.3 Методика (проверенная, а не «своя выдуманная»)
Брать общепринятые индикаторы и описывать их на странице «Методика»:
- Число публикаций по годам, рост; доля открытого доступа (OpenAlex `open_access`).
- **FWCI** — нормированная по области цитируемость (поле OpenAlex `fwci`), и
  `citation_normalized_percentile` (доля работ в топ-1%/10% своей области) —
  подход как в Leiden Ranking (CWTS): PP(top 10%), MNCS.
- Международное соавторство (доля работ с соавторами из других стран), партнёры
  (организации и страны), граф соавторства.
- Темы и их рост, «сильные стороны» (темы, где FWCI > 1).
- Для одного учёного: h-индекс, i10 (OpenAlex `summary_stats`), работы, темы, соавторы.
- Пересчитывать только из исходных данных, показывать дату выгрузки и источник.

## 6. Технические уроки (чтобы не наступать снова)
- Новая доска + стартовые карточки пишутся одним пакетом → в правилах для записей
  использовать `getAfter()`; сразу после создания чтение может получить «нет прав» —
  поэтому потоки обёрнуты в `retryDenied` (`board_service.dart`).
- Правила $…$: `$5 и $10` — не формула (см. CLAUDE.md, раздел «Формулы»); правила в
  `math_markdown.dart` и `models/note.dart` должны совпадать.
- Разбор Markdown для выгрузки — `encodeHtml: false`, иначе «&» → «&amp;».
- В тестах: `rootBundle`/файлы — через `tester.runAsync(...)`; бесконечный спиннер
  ломает `pumpAndSettle`; шрифты KaTeX в тестах имеют семейство
  `packages/flutter_math_fork/KaTeX_*`; `pageBack()` не работает на домашнем экране.
- .tex проверять настоящей компиляцией: `pdflatex -interaction=nonstopmode note.tex`
  (TeX Live ставится скриптом настройки среды).
- Тесты правил Firestore:
  `cd firestore_tests && ln -sfn ~/rules-tools/node_modules node_modules && npx firebase emulators:exec --only firestore --project demo-scinode "node --test rules.test.mjs"`
  (если порт занят: `pkill -f cloud-firestore-emulator`). Ошибки `PERMISSION_DENIED`
  в логе — это ожидаемые `assertFails`, смотреть на `# pass / # fail`.
- Скриншоты экранов для самопроверки: виджет-тест с загрузкой шрифтов Roboto из
  `$HOME/flutter/bin/cache/artifacts/material_fonts` и сохранением PNG в scratchpad.
- Справочник направлений: `assets/taxonomy/openalex_v2.json` (скачан из
  github.com/ourresearch/openalex-topic-classification, v2/data/topics/topics.json),
  переводы — `lib/strings_subfields.dart`.
