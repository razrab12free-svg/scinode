## 4. Окружение — что владелец настраивает сам (с компьютера или в настройках)
Почему так: запрос «изменить среду» нельзя подтвердить с телефона, поэтому владелец
вносит изменения сам — меню среды в заголовке сессии → среда **scinode** → **Edit**
(или claude.ai/code в браузере, режим «Версия для ПК»). Новые настройки видны только
в **новой** сессии. Инструкция: https://code.claude.com/docs/en/cloud-environments#network-access

1. **Переменная окружения** `OPENALEX_API_KEY` — ключ с https://openalex.org/settings/api
   (значение не печатать и не показывать!).
2. **Network access** → уровень **Limited**, галочка **Allow package managers** — оставить,
   в **Allowed domains** — все строки из `docs/network_allowlist.txt` (по одной на строку).
3. **Setup script** — текст файла `tools/cloud_setup.sh` целиком (ставит Flutter, Java,
   poppler, TeX Live, инструменты Firestore, Python-пакеты Аналитики).
4. **GitHub:** секрет `OPENALEX_API_KEY` (Settings → Secrets and variables → Actions);
   Pages — Source: GitHub Actions.

**Проверка в начале сессии** (ничего не печатать из ключа):
```
export PATH="$HOME/flutter/bin:$PATH"
curl -sS -o /dev/null -D - "https://api.openalex.org/works?per_page=1&select=id&api_key=$OPENALEX_API_KEY" | grep -iE "^HTTP|x-ratelimit-remaining:"
while read h; do echo "$(curl -sS -o /dev/null -m 10 -w '%{http_code}' https://$h) $h"; done < docs/network_allowlist.txt
flutter test && (cd analytics && python3 -m pytest -q tests)
python3 -c "import rapidfuzz, pandas, numpy; print('ok')"
```
`000`/403 от прокси — адрес закрыт: назови владельцу точный адрес.

**Лимит OpenAlex:** $1 в день (≈ 10 000 запросов) **на аккаунт** — второй ключ того же
аккаунта не помогает; сброс в 00:00 UTC = 05:00 Ташкент. Полный расчёт ≈ 8 300
запросов. Не гонять полные расчёты локально в день запуска на GitHub; для проверок —
`--only <id>`, без ключа — общий лимит $0,10 на IP (только пробные запросы).
Второй аккаунт OpenAlex ради лимита не заводить (правила); при нужде — докупка по $1.

## 6. Дальше: усиление Аналитики по этапам (`docs/analytics_architecture.md`)
**Этап 1 — «потерянные» работы (начато, черновик в `affiliations.py`).** Что выяснено
живыми запросами 6.11.2026:
- Лучший способ — `GET /raw-affiliation-strings?q=<название>&unmatched-institutions=<I…>&per_page=100`
  (различные строки + `works_count`, `institution_ids_final`, `countries`, сортировка по
  `works_count`). `q` нестрогий (совпадение слов) → каждую строку проверять rapidfuzz.
  Проверить: работает ли `q` с `"A" OR "B"` на этом адресе (на `/works`
  `raw_affiliation_strings.search:"A" OR "B"` работает).
- Пример НУУз (I47151758): строки «University of Uzbekistan named after Mirzo Ulugbek,
  Tashkent…» привязаны к Академии наук (ошибка); строки на русском/узбекском часто без
  организации; «Jizzakh branch of the National University of Uzbekistan» — отдельная
  организация I4392021094, не в lineage НУУз (вопрос иерархии ROR).
- **Правила OpenAlex** (прочитать целиком: `help.openalex.org/access/fixing-errors/ai-curation-guide.md`
  и `.../affiliations.md`): исправлять может только платный участник; остальным —
  заявка https://openalex.org/contact; добавления так же опасны, как удаления;
  спорное → «на проверку человеком»; филиалы, иерархия и переводы названий —
  исправлять в ROR (бесплатно, ror.org/curation); работать по строкам (byte-exact), не по работам.
- Продукт для вуза: список строк (без организации / чужая организация / филиал) с
  числом работ → готовая заявка в OpenAlex + что поправить в ROR.
- **Проверено 7.11.2026 на 4 вузах** (функция `lost_strings`, тесты
  `analytics/tests/test_affiliations.py`, образцы `fixtures/raw_affiliations/`):
  - на этом адресе работает точная фраза `q="<название>"`, а `"A" OR "B"` — **нет**
    (0 строк) → 1 запрос на вариант названия (до 3) + 1 запрос `/institutions` за
    названиями привязанных организаций;
  - **главная находка — филиалы:** Джизакский филиал НУУз (939 работ) и Самаркандский
    филиал ТГЭУ (342 работы) не входят в lineage головного вуза — это иерархия ROR
    (предложить вузу связь parent/child в ROR);
  - строк без организации мало (НУУз — 5 строк/10 работ на русском, ТГЭУ — 10/14 на
    узбекском): matcher OpenAlex v3 хороший; у пед. университета им. Низами — 0

  - правило страны: строка с известной страной не своей страны — не наша

  - ручная проверка: ~16 из 18 найденных строк верны; строки с названием

- Проверка точности классификатора: вручную 100 строк по 3 вузам, цель ≥ 95 %.

## 10. Технические уроки
- Числа и проценты — с неразрывным пробелом (` `), в тестах — `formatMoney`/`formatShare`.
- В шрифте PDF нет «→»; в `pw.Stack` не класть пустой непозиционированный виджет.
- Длинные суммы в `_BigNumber` — подпись под числом (иначе переполнение на 360 px).
- Crossref журнала — `works?filter=issn:…&rows=0`, не `/journals`.
- OpenAlex: 429 с огромным `Retry-After` = лимит дня; `type`-ключи group_by — URL
  (`short_id`); `apc_paid.value_usd:!null` не работает, используйте `:>0`; group_by
  с `cursor=*` для > 200 групп; `has_doi`, `has_orcid` — для качества данных.
- Сверхплодовитость без `authors_count:<101` даёт физиков ЦЕРН.
- Образцы для тестов записывать «гибридом»: есть образец — из него, нет — живой запрос
  с записью (не перезаписывать старые образцы — изменятся проверяемые числа).
- Виджет-тесты длинных списков — `scrollUntilVisible` с шагом 300–400 или `drag`.
