- **GitHub:** секрет `OPENALEX_API_KEY` (Settings → Secrets and variables →
  Actions), Pages — Source: GitHub Actions. Данные:
  `https://x9096730-spec.github.io/scinode/analytics/v1/index.json`.
- **Адреса сети** — `docs/network_allowlist.txt`. Проверка доступа:
  `curl -sS -o /dev/null -w "%{http_code}" <адрес>`; `000`/403 от прокси — адрес
  закрыт → назови его мне. **Не открыты** (владелец пока отказал): `zenodo.org`,
  `open.leidenranking.com` (данные Лейденского рейтинга). Закрыты и не нужны:
  `www.elsevier.com`, `www.scimagojr.com` (см. лицензии ниже).
- **Лимит OpenAlex:** 10 000 запросов в день ($1) на ключ, сброс в 00:00 UTC.
  Остаток — заголовок `X-RateLimit-Remaining`. Полный расчёт ≈ 6 000 запросов.
  **Не гонять полные расчёты локально в день запуска на GitHub.** Для локальных
  проверок — `--only <id>` / `--limit N`. Совет владельцу: отдельный ключ для GitHub.
- Ключ OpenAlex берётся на https://openalex.org/settings/api (бесплатно).

## 5. Scinode Аналитика — как устроена (кратко; подробно — analytics/README.md)
- `analytics/scinode_analytics/`: `client.py` (OpenAlex + `get_url` для других API,

- Организации: OpenAlex `country_code:UZ`, все типы кроме company, ≥100 работ за

- Показатели: публикации по годам и типам; открытый доступ; PP(top 10%) и
  PP(top 1%) — **по всем и по собственным работам** (`corresponding_institution_ids`);
  доли FWCI>0 и >1 (медиана почти у всех 0 — не используем); мегаколлаборации
  (`authors_count:>100`); «сильные» направления — только по своим работам,
  ≥30 работ, нижняя граница Уилсона >10 %; партнёры (страны, организации, доля
  международных); топ-авторы; топ-журналы (DOAJ, Crossref, рост объёма);
  отозванные (`is_retracted`); доля работ только в репозиториях; проверка
  цитирования 10 топ-работ; ROR-данные.
- Приложение: `lib/models/analytics.dart`, `lib/services/analytics_service.dart`
  (кэш 24 ч), `lib/screens/analytics_screen.dart`, `lib/widgets/analytics_charts.dart`,
  `lib/services/analytics_pdf.dart`. Образцы — `test/fixtures/analytics/` (настоящий
  расчёт 8 организаций + UZ).
- **Ключевые находки (говорить честно на презентации):** PP(top10%) по всем
  работам завышен «гостевым» соавторством почти вдвое (НУУз 9,0 % → 5,1 %,
  ТГЭУ 11 % → 5,2 %, пед. им. Низами 8,8 % → 3,5 %); по Узбекистану 639 отозванных
  статей за 2021–2025; среди главных журналов вузов есть издания без DOI

- **Лицензии:** OpenAlex, ROR, OpenCitations, Crossref (метаданные) — свободно.

## 6. Как усилить Аналитику (план; перед каждым пунктом — curl и спроси меня)
Принципы мировой практики, на которые опираться и ссылаться в методике:
**Лейденский манифест** (2015, 10 принципов ответственной метрики), **DORA**
(не оценивать учёных по импакт-фактору журнала), **CoARA** (2022, реформа оценки
исследований в Европе), методика **Лейденского рейтинга CWTS** (нормировка по
области, PP(top 10%), дробный учёт, интервалы устойчивости). Главное: не один
«балл», а набор показателей с контекстом, сравнение с похожими организациями,
прозрачные данные и формулы. *Даты и формулировки — проверить по первоисточникам.*

**Быстро и бесплатно на данных OpenAlex (по 1–2 запроса `group_by` на вуз):**
1. **Цели устойчивого развития (ЦУР/SDG)** — `group_by=sustainable_development_goals.id`:
   вклад вуза в ЦУР (нужно для THE Impact Rankings и министерства).
2. **Языки публикаций** — `group_by=language`: доля узбекских/русских/английских работ.
3. **Кто финансирует** — `group_by=grants.funder` (поле может называться иначе в
   новой схеме — проверить curl): фонды, указанные в работах.
4. **Расходы на публикацию (APC)** — поле `apc_paid`/`apc_list` (оценка денег,
   потраченных на платный открытый доступ) — очень полезно вузам.
5. **Сверхплодовитые авторы** — >72 работ в год (порог Иоаннидиса): пометка,
   а не обвинение.
6. **Несоответствие профилю** — доля работ в направлениях, где «своих» работ
   мало (мы уже нашли такой эффект у пед. университета) — отдельный индикатор.
7. **Сравнение с соседями** — те же отчёты для Казахстана, Кыргызстана,
   Таджикистана (country_code KZ, KG, TJ) — региональный бенчмарк (≈ ещё 2–4 тыс.
   запросов в месяц: разнести по дням или отдельный ключ).
8. **Дробный учёт** (как в Лейдене) — доля вуза в работе = его авторы / все
   авторы; требует списков работ — сначала оценить стоимость запросов.
9. **Интервалы устойчивости** для PP(top 10%) вуза (уже есть `wilson_low`) —
   показывать «± ».

**Другие открытые источники (сначала проверить условия и доступ):**
- **OpenAIRE Graph API** (`api.openaire.eu`) — проекты и гранты (в т. ч. ЕС),
  связанные с вузами Узбекистана.
- **DataCite** (`api.datacite.org`) — наборы данных и программы с DOI.
- **Лейденский рейтинг Open Edition** (CC0, zenodo.org) — сверка нашей методики.
- **VOSviewer** (бесплатная программа CWTS) — карты соавторства и тем; можно
  выгружать наши данные в его формат для вузов.
- **Retraction Watch Hijacked Journal Checker** — список «угнанных» журналов
  (проверить лицензию перед использованием).
- **ОАК Узбекистана** (Высшая аттестационная комиссия) — перечень признанных
  журналов: найти официальный машиночитаемый список и условия; это главный
  национальный стандарт, важен для вузов.
- **Uzbekistan Research Online** и сайты местных журналов — покрытие узбекских
  изданий в OpenAlex неполное; честно указывать это в методике.

**Центральная Азия — что учесть:** в Узбекистане и соседях оценка вузов и
учёных во многом идёт по Scopus/Web of Science и национальным перечням (ОАК),
а также по рейтингам QS/THE; растёт число публикаций в сомнительных журналах и
конференциях — поэтому наша сильная сторона: **прозрачность и проверка качества**
(собственные работы, отозванные статьи, журналы без DOI, рост объёма, самоцитирование).
*Конкретные нормативы министерств и цифры — проверять по официальным источникам
перед тем, как писать их в продукте.*

## 8. Безопасность (чек-лист)
- Секретов в коде нет; ключ OpenAlex — только в переменной среды и секрете GitHub;
  в образцах ответов ключ не сохраняется (проверка: `grep -r "$OPENALEX_API_KEY"`).
- Ссылки из внешних данных — только через `openLink` (http/https).
- Публикуемые на Pages данные — только открытые сведения (без личных данных
  пользователей приложения).
- Firestore: правила в `firestore.rules`, тесты эмулятора — перед любым изменением.
- Посоветовать владельцу (бесплатно, Settings репозитория): **Dependabot alerts**,
  **Secret scanning**, **Branch protection** для `main` (PR + зелёные проверки).
- В Actions предупреждение «Node.js 20 is deprecated» — отдельной задачей обновить
  версии `actions/*` (кроме логики подписи), проверив сборку.
- Обновления пакетов: `flutter pub outdated`; обновлять только отдельным PR с
  полным прогоном тестов; `pubspec.lock` хранится в репозитории.
