# Архитектура «Scinode Аналитики»

Цель: прозрачная, воспроизводимая и проверяемая аналитика науки вузов
Узбекистана (позже — Центральной Азии) на открытых данных. Принципы —
Лейденский манифест, DORA, CoARA: набор показателей с контекстом, а не один балл;
нормировка по области; честно указанная точность; возможность проверки и
исправления самой организацией.

## Слои (как есть и как должно быть)

```
 1. Источники        OpenAlex · Crossref · ROR · OpenCitations · DOAJ · (OpenAIRE, Leiden, ОАК)
        │  client.py: ключ, лимит, повторы, запись образцов, BudgetExhausted
 2. Сбор             build.py: запросы group_by/фильтров (без скачивания всех работ),
        │            ~57 запросов OpenAlex на вуз; внешние API — get_url
 3. Расчёт           metrics.py, affiliations.py: ЧИСТЫЕ функции, тесты на записанных ответах
        │
 4. Контроль         quality (уровень доверия), audit (выборочная проверка), lost (потерянные
        │            работы), сравнение с прошлым месяцем (скачки), проверка схемы
 5. Публикация       JSON на GitHub Pages (v1/index.json, orgs/<id>.json, history.json);
        │            при сбое — ничего не публикуется, на сайте остаются прошлые данные
 6. Приложение       models/analytics.dart → экраны, сравнение, PDF (3 языка)
```

## Правила, которые нельзя нарушать
1. **Не выдумывать данные.** Каждое поле API — сначала живой запрос и образец.
2. **Чистые функции и тесты.** Любой показатель — функция в `metrics.py`/
   `affiliations.py` + тест на настоящем образце + сверка с независимым способом
   (полный список работ, другой источник) хотя бы один раз.
3. **Формат JSON.** Добавлять поля можно; менять/удалять — только с новой схемой
   (`SCHEMA`, папка `v<N>`, `analyticsSchema` в приложении).
4. **Бюджет OpenAlex.** Новый показатель — сначала посчитать запросы на вуз
   (`REQUESTS_PER_ORG`). Предел — 10 000 в день на аккаунт. Дорогие проверки — по
   выборке или раз в квартал.
5. **Ничего не публиковать при сбое.** BudgetExhausted (код 3), HistoryUnavailable
   (код 4), > 10 % ошибок (код 1).
6. **Личные данные.** Имена — только там, где это открытая наука и владелец разрешил
   (ведущие авторы); сверхплодовитые авторы — без имён.
7. **Автоматически не «приписывать» вузу работы.** Спорные строки — «на проверку
   человеком» (правила OpenAlex: help.openalex.org/access/fixing-errors/ai-curation-guide.md).

## Что даёт точность (план по этапам)
| Этап | Что | Как проверить | Стоимость |
|---|---|---|---|
| 1 | «Потерянные» работы: `/raw-affiliation-strings?q=<название>&unmatched-institutions=<id>` + rapidfuzz; виды: без организации / чужая организация / филиал; список строк с `works_count` для заявки в OpenAlex и подсказки для ROR | ручная разметка 100 строк по 3 вузам, точность классификатора ≥ 95 % | ~3 запроса на вуз |
| 2 | Выборочная проверка: `sample=50&seed=<ГГГГММ>`; совпадение строки места работы с названием (точность привязки ± интервал), год по Crossref | сверка вручную 20 работ | 1 запрос OpenAlex + до 20 Crossref |
| 3 | Скачки: показатель изменился за месяц сильнее порога → пометка | тест на истории | 0 |
| 4 | Архив сырых ответов месяца (воспроизводимость) | повторный расчёт из архива даёт те же числа | 0 запросов, место на диске |
| 5 | Сверка с Лейденским рейтингом Open Edition (нужен zenodo.org) | расхождение PP(top 10%) для вузов из рейтинга | 0 OpenAlex |
| 6 | Дробный учёт (доля вуза в работе) | сверка с Лейденом | дорого — по выборке |
| 7 | Сравнение с похожими (тип, размер) и соседями (KZ, KG, TJ) | — | +2–4 тыс. запросов/мес |
| 8 | ОАК Узбекистана: перечень журналов | — | внешний источник |
| 9 | Сверка APC с OpenAPC | доля совпадений | 0 OpenAlex |

## Где что лежит
- `analytics/scinode_analytics/client.py` — доступ к API, лимиты, повторы.
- `analytics/scinode_analytics/build.py` — сборка отчётов и публикация.
- `analytics/scinode_analytics/metrics.py` — показатели.
- `analytics/scinode_analytics/affiliations.py` — потерянные работы, выборочная проверка (черновик, не подключён).
- `analytics/tests/` — тесты; `fixtures/openalex` (ответы OpenAlex), `fixtures/external`.
- `analytics/requirements.txt` — разрешённые пакеты с точными версиями.
- `analytics/README.md` — методика для людей (публичная).
- `lib/models/analytics.dart`, `lib/screens/analytics_screen.dart`,
  `lib/services/analytics_pdf.dart`, `lib/strings_analytics.dart` — приложение.
